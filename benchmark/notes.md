## Development log — what we changed because of what we measured

**First pass (archived in [`benchmark/archive/`](../benchmark/archive/); Codex 0.148, reasoning *high*, one run per cell).** On the showreel prompt the *no-skill* Codex film (frame fill 32 %, 0 % static) beat the first Cinewright 2.1 build (frame fill 6 %, 21 % static, three perfunctory review files, no picture ever looked at). On a second task, a 6-second logo sting, the skill run spawned a sound sub-agent and then sat until the 50-minute timeout without a film, while the same task without the skill finished in 12 minutes. We treated both as bugs **in the skill**, not in the benchmark:

- `qc.mjs look` (frame fill) became a gate and the protocol got a measured **boldness floor** (median fill ≥ 25 %): "go all out" means spectacle, not thin lines on black;
- `qc.mjs craft` now rejects rubber-stamp reviews — a real review names the scene, the cause and the exact change, and it is written after looking at frames;
- SKILL.md says *fork a template, don't start from a blank page*, and never to spawn unattended sub-agents;
- the runner got hard timeouts that cannot hang on orphaned child processes, and (later) automatic retries for dropped connections.

The headline results above are the re-run with those fixes, at **xhigh** reasoning on two models. They are a first data point, not a verdict: one run per cell, and the no-skill baseline at xhigh is a strong film too — Codex without the skill wrote a small GPU renderer in Python and delivered a bold, well-designed reel. What the skill adds in these runs is **range** (more disciplines in 15 s: GPU particles, chrome 3D, liquid shaders, UI motion), **a mixed soundtrack with dynamics** (the baseline's loudness range is almost flat), **fewer static stretches**, and a written, gated process — at several times the token cost.

**Second pass (four art-directed prompts, Codex · gpt-6-astra · xhigh).** A sci-fi interface boot, a product-launch film (ARC), a sci-fi teaser (LAST SIGNAL) and an audio-reactive visualizer. The skill won one clearly (the interface: frame fill 9 → 26 %, static time 82 → 25 %), split on LAST SIGNAL, and **lost two**: for ARC the skill run drew the titanium ring as a thin 2D circle (13 % fill, 64 % of the film near-static) and shipped it after accepting its own warnings; the visualizer run was still polishing when the 75-minute timer ended. Both are bugs of the skill, so we changed the skill, not the benchmark:

- the pacing and frame-fill checks became hard **FAIL**s (median fill < 15 %, more than half the film near-static) unless the brief declares a deliberate `Restraint: …`, and `craft` warns when a film uses nothing but flat 2D canvas;
- a hero *object* is a lit 3D mesh, never an outline — the atlas got the recipe `product-ring-macro` (environment-lit ring, floor reflection, macro dolly, exploded view);
- the protocol has a **time-box**: ship a first complete deliverable right after the skeleton and overwrite it as polish rounds land, so a timer can no longer leave a project without a film.

**Third pass (everyday prompts, Codex · gpt-6-astra · xhigh).** After the second pass the project owner redirected the work: most real requests are not 3D showpieces but a person intro, a channel intro, a promo, an infographic — *simple* motion graphics that should simply look good. So the skill got a motion-graphics kit (the film is a JSON spec; picture and sound are both generated from it) and the benchmark got a suite of five plain-language prompts ([`benchmark/suite/simple.json`](../benchmark/suite/simple.json)). Baselines first, then the skill runs from a snapshot of the skill taken before the last polish of the kit. What came out, honestly:

- **Introduce a person:** frame fill 14 → 50 %, near-static time 57 → 0 %, at 2.8× the tokens. The with-skill film is a different *design* (bold colour blocks, a 3D cursor, interface rows with toggles), not the same film with more motion.
- **Vertical social promo:** a draw on design (frame fill 36 vs 37 %) — unaided, Codex already lays out a very good poster-style promo; the skill removed the static stretches (41 → 0 %) and added a brief and three review rounds, at 3.6× the tokens and 1.7× the time.
- **Channel intro:** frame fill 9 → 31 %, near-static time 57 → 14 %, at 5.1× the tokens and 1.7× the time. The mark is now built from lit 3D cubes instead of flat squares. One honest loss: the no-skill sting has the *wider* loudness range (7 vs 0.7 LU — a quiet start and one big hit); the with-skill mix is flatter.
- **Animated infographic:** frame fill 12 → 26 %, near-static time 73 → 8 %, loudness range 0.8 → 2.2 LU, at 2.8× the tokens and 1.2× the time. Again a different design: a bold poster style with drawn moon, brain and clock characters instead of dark cards.

Operational notes, because they affect how to read the table: the skill runs were scheduled in two parallel queues and the first attempts of two jobs ended after about 13 minutes when the gateway between Codex and the model reported a usage limit — they were re-run from scratch (the person-intro film is its third attempt; `attempts: 3` in its summary). Later a network error silently hung two more jobs for 25 minutes, which is why the runner now has a stall watchdog (`--stall-min`); then the model gateway on the test machine stopped answering for about 50 minutes, and the channel-intro and infographic runs were started again from scratch once it was back. The skill snapshot used for all four runs was taken before the last polish of the kit (the shipped 2.2.0 kit has since gained ambient motion, so that every preset passes the pacing gate as shipped).
